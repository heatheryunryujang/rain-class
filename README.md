# 비 오는 날, 우산이 없다면? — 설정 안내

휴대폰으로 하는 10분 시뮬레이션이에요. 1부에서 2학년 아이가 되어 등굣길을 걷고, 2부에서 선생님이 되어 그 질문들로 수업을 설계해요.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 시뮬레이션 (학우들이 여는 화면) |
| `view.html` | `?id=…` 개인 설계안 보기 · `?all` 모아보기(발표 화면) |
| `invite.html` | 발표자 준비: 카드 보내기, 설정 점검, 바로가기 |
| `config.js` | 주소와 키 세 개를 넣는 곳 |
| `Code.gs` | 구글 시트에 붙일 Apps Script (GitHub에는 안 올려도 돼요) |
| `images/` | 장면 그림, 친구 얼굴, 카드 이미지 |

## 1. GitHub Pages에 올리기 (5분)

1. GitHub에서 **New repository** → 이름 예: `rain-class` → **Public** → Create.
2. **Add file → Upload files**에 이 폴더 안의 내용을 통째로 끌어다 놓기 (`images` 폴더 포함, `Code.gs`는 빼도 됨) → Commit.
3. **Settings → Pages** → Source: *Deploy from a branch*, Branch: `main` / `(root)` → Save.
4. 1~2분 뒤 위에 뜨는 주소를 복사. 예: `https://아이디.github.io/rain-class/`

## 2. 구글 시트 연결 (5분)

1. 새 구글 시트 만들기 (이름 예: `비오는날 설계안`).
2. **확장 프로그램 → Apps Script** → 기본 코드를 지우고 `Code.gs` 내용 붙여 넣기 → 저장.
3. **배포 → 새 배포** → 톱니바퀴에서 **웹 앱** 선택
   - 실행: **나**
   - 액세스 권한: **모든 사용자**
4. 배포 → 권한 허용 (‘확인되지 않은 앱’ 화면이 나오면 *고급 → 이동*).
5. 나온 **웹 앱 URL**(`…/exec`로 끝남)을 복사.
6. 시트를 새로고침하면 위에 **발표 도구** 메뉴가 생기고 `제출`·`테스트`·`보관` 탭이 만들어져요.

> Code.gs를 고친 뒤에는 **배포 → 배포 관리 → 연필 → 버전: 새 버전**으로 다시 배포해야 반영돼요. 주소는 그대로예요.

## 3. 카카오 디벨로퍼스 (5분)

1. <https://developers.kakao.com> 로그인 → **내 애플리케이션 → 애플리케이션 추가** (앱 이름 예: 비 오는 날 수업).
2. **앱 → 플랫폼 키 → JavaScript 키**: 키를 복사하고, 같은 화면의 **JavaScript SDK 도메인**에 `https://아이디.github.io` 등록.
3. **앱 → 제품 링크 관리 → 웹 도메인**에도 `https://아이디.github.io` 등록 (카드 버튼 링크가 열리게 하는 설정).

도메인은 `https://아이디.github.io`까지만 써요. 뒤의 `/rain-class/`는 넣지 않아요.

## 4. config.js 채우기

GitHub에서 `config.js` → 연필 아이콘 → 세 칸 채우고 Commit.

```js
window.APP_CONFIG = {
  SITE_URL: "https://아이디.github.io/rain-class/",   // 끝에 / 꼭
  KAKAO_JS_KEY: "복사한 JavaScript 키",
  SCRIPT_URL: "https://script.google.com/macros/s/…/exec"
};
```

JavaScript 키는 웹 페이지에 드러나도록 만들어진 키라 공개 저장소에 올려도 괜찮아요. 등록한 도메인에서만 작동해요. (REST API 키나 Admin 키는 절대 넣지 마세요.)

## 5. 리허설

`https://아이디.github.io/rain-class/invite.html`을 열어요.

- **설정 점검**의 네 줄이 모두 ✓인지 확인.
- **리허설 카드 보내기** → 나와의 채팅으로 보내기 → 카드 눌러 끝까지 해 보기.
  - 리허설 주소(`?test`)로 낸 설계안은 시트의 `테스트` 탭에 따로 쌓여요. 발표 화면에는 안 섞여요.
  - 마지막에 *제출하고 단톡방에 보내기* → 나와의 채팅에 내 설계안 카드가 오는지 확인.
- **리허설 모아보기**에서 내 설계안이 붙는지 확인.
- 다 되면 시트에서 **발표 도구 → 테스트 기록 비우기**.

## 6. 발표 당일

1. 발표 직전 `invite.html` → **단톡방에 카드 보내기** → 과 단톡방 선택.
2. 발표 노트북에 `view.html?all`(모아보기)을 띄워 두기. 15초마다 새 설계안이 붙어요. 카드를 누르면 크게 보여요.
3. 발표가 끝나면 **발표 도구 → 시연 데이터 보관하기**. `제출` 탭이 비고 `보관` 탭으로 옮겨져요. 학우들이 받은 개인 링크는 계속 열려요.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 제출 버튼을 누르면 “저장이 안 됐어요” | Apps Script 배포 액세스가 **모든 사용자**인지, `SCRIPT_URL`이 `/exec`로 끝나는지 |
| “카카오 공유가 안 돼요” | `KAKAO_JS_KEY`, **JavaScript SDK 도메인** 등록 |
| 카드는 가는데 눌러도 안 열림 | **제품 링크 관리 → 웹 도메인** 등록, `SITE_URL` 끝의 `/` |
| 고쳤는데 그대로 | 휴대폰 브라우저 캐시. 주소 뒤에 `?v=2`를 붙여 열어 보기 |
| 하던 화면이 그대로 남아 있음 | 앱이 휴대폰에 진행 상황을 저장해요. 설계안 화면의 **처음부터** 버튼 |

언제든 학우들은 **텍스트 복사**로 설계안을 단톡방에 붙여 넣을 수 있어요. 시트나 카카오가 막혀도 발표는 이어 갈 수 있어요.
